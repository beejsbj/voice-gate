# Similar Jev projects and useful implementation patterns

Researched 2026-09-20. These are public-source findings, not reproduced performance claims. I inspected the named implementation files at the pinned revisions below; I did not run these applications or their tests. No third-party code was copied into the engine. Discovery directories helped locate projects; implementation conclusions come from the original repositories and TypeSafe documentation.

## Five recommendations for this engine

These are design recommendations derived from the inspected projects, not claims that those projects implement this exact API.

1. **Make transcripts the portable boundary.** A final text submission should need only authenticated HTTP plus a session/utterance ID. Keep raw speech recognition in the Mac, phone or browser client. Return a stable JSON decision containing the original text, outcome, reasons, model information and timing. This combines Jev Voice's separation with Voice Browser's shared typed/speech path.
2. **Make repeats and revisions safe.** Bind an utterance to a session, track its revision and final state, and make client retries idempotent. Cancel or discard obsolete model responses before capture/handoff. Require a final payload before dispatch. Voice Browser supplies the practical motivation; strict idempotency and revision semantics are our deployment adaptation.
3. **Expose adapters around one core.** HTTP should be the common interface; CLI, menu-bar, mobile Shortcut and MCP should call it. Configure assistant destinations server-side by stable ID. Return a handoff receipt and preserve the original command. The host adapter owns execution. HA-Jev and JevRouter show why this boundary keeps integrations small.
4. **Expose uncertainty and usage.** Include explicit ignore/wait/review/error outcomes, relevant distributions and deterministic policy reasons. Track request count, latency and token usage; bound concurrent work and request size. A timeout must not turn into a positive decision or repeated execution. The browser controller, HA-Jev budget and TypeSafe's confidence guidance support this approach.
5. **Keep captures literal and attributable.** Save exact source text with session/utterance identity. Treat remembered content, requests to recall, reminders and assistant commands as distinct outcomes. Preserve corrections and user edits as evidence. Capture's boundary/classification passes are a concrete reference for later multi-thought support.

## Official constraints checked

- The [current official skill](https://raw.githubusercontent.com/typesafe-ai/skills/main/skills/typesafe-ai/SKILL.md) keeps execution, exact lookup and arithmetic in code; it recommends inspecting the live API and relevant cookbook before implementation.
- The [JavaScript SDK documentation](https://docs.typesafe.ai/sdk/javascript) shows `TypeSafeClient.systemOne` with typed question helpers. The engine should select credentials, base URL and model from deployment configuration; no host-specific secret launcher belongs in the public default.
- [Confidence](https://docs.typesafe.ai/confidence) distinguishes the Choice/Score `confidence` statistic from their full probability distributions; Noul does not have that separate field. Thresholds require evaluation on the actual application, rather than copying a demo's cutoff.
- [Intent routing](https://docs.typesafe.ai/patterns/intent-routing) and [confidence routing](https://docs.typesafe.ai/patterns/confidence-routing) place handler selection and fallback policy in ordinary code. A model's certainty is not permission to act.

## Verification boundary

This investigation verifies implementation presence by source inspection. It does not certify these repositories for production, validate their benchmarks, prove microphone behavior on a physical Mac/phone, or establish compatibility with every Codex, Claude, Hermes or T3 release. The new engine needs its own tests and real deployment checks. Keep native menu-bar packaging and device microphone trials labeled as unverified until exercised on those devices.
